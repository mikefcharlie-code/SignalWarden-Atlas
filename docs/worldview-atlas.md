# SignalWarden Atlas map

Atlas opens the existing Mark 2 World View at **30.83857, -83.26409**, with a reference map zoom of **5.03**. The original perspective globe uses its own camera scale, so the app converts the conventional map zoom approximately and labels both values; this is not a Web Mercator map renderer. The initial location, zoom, basemap choice, and supported layer hints can be read from `lat`, `lon`, `z`, `base`, `layers`, and `sig` URL parameters. Values are range-checked. URL layer hints select display filters only and never grant permission to contact a provider.

## Satellite source and network gate

NASA GIBS VIIRS SNPP corrected-reflectance true color is preselected as the satellite option. The schematic globe remains visible offline; **no tile requests occur until the user opens the satellite source panel and checks “Allow tile requests.”** Tile loading stays limited to the visible globe viewport, rate-limited and bounded in count and size. Attribution, selected imagery date, retrieval/provider time, and freshness remain visible with the source details. The GIBS date defaults to yesterday because the current day's composite may still be filling in; clouds, swath gaps, and image age are normal. This is satellite context, not a high-resolution local survey or a live sensor view.

NASA asks clients to acknowledge the use of imagery from NASA's Global Imagery Browse Services, part of NASA's Earth Science Data and Information System. See [NASA GIBS API guidance](https://www.earthdata.nasa.gov/engage/open-data-services-software/earthdata-developer-portal/gibs-api) and [NASA data-use and citation guidance](https://www.earthdata.nasa.gov/engage/open-data-services-software-policies/data-use-guidance). No NASA imagery is bundled into the repository.

The existing optional Esri World Imagery and Google 2D satellite relay controls remain available only where the server relay is enabled and configured. Esri's [World Imagery item](https://www.arcgis.com/home/item.html?id=10df2279f9684e4a9f6a7f08febac2a9) describes lower-resolution global coverage and higher-resolution imagery typically within 3–5 years of currency for most areas; actual source dates and coverage vary by location. These keyed services are not selected by default and were not verified with real production keys in this task.

## Signal controls

- **Aircraft / planes:** filters the existing aircraft display. Offline examples are synthetic; the optional adsb.lol read is a bounded, manual, receive-only context feed.
- **Camera locations:** filters synthetic or explicitly imported camera points.
- **Live cameras:** filters public traffic-camera catalog results. A catalog entry or snapshot is not an onboard aircraft stream; there is no recognition, plate reading, or cross-camera tracking. Fetching requires the existing traffic relay, provider allowlist/configuration, and a separate manual request.
- **AIS vessels:** filters vessel observations. AIS remains receive-only and self-reported/incomplete; the display checkbox is not the AIS session opt-in. The relay has its own explicit opt-in and manual refresh.
- **Road incidents:** filters TomTom aggregate incident results. A deployment must enable the public-traffic and TomTom relay flags and configure a server-side key; the map switch itself does not fetch.
- **Road works** and **road closures:** separate display filters for Georgia 511 / GDOT Events API records. The layer filters do not fetch; loading the feed requires the existing World View network opt-in, the public-traffic relay, server configuration (`UCAS_511GA_ROAD_EVENTS_ENABLED=1` plus `UCAS_511GA_API_KEY`), and a manual refresh in the public traffic panel. 511GA states support for Georgia interstates and state routes; local-road completeness is not documented. Source attribution, retrieval time, event update time, stale status, and provider errors remain visible. Empty or missing results do not prove roads are clear.

Provider data remain subject to coverage, freshness, source attribution, terms, and deployment configuration. No provider data is bundled. The [Georgia 511 API documentation](https://511ga.org/developers/doc) requires a registered account and developer key and documents a ten-call-per-60-second limit; the relay adds stricter request bounds, caching and throttling. The provider panels preserve the existing bounded-read and source-status behavior.

## Trust and coverage evidence

The **Loaded source evidence** list is a descriptive, visible inventory built only from data already in memory: loaded point observations, provider results, and explicit source summaries when a panel supplies them. It does not claim a provider summary that the provider did not emit. If attribution, license, terms URL, source URL, coverage, time basis, retrieval time, or error state is not supplied or safely available, the UI shows **Not reported**, **Unknown**, or an equivalent unknown state. Safe error text is sanitized before display; no credentials or sensitive request details are exposed.

Freshness and data kind are separate fields. Freshness can be fresh, stale, failed, synthetic, unknown, or mixed; data kind identifies categories such as observation, reported event, forecast, delayed, modelled, synthetic, geometric estimate, imagery, or unknown. A forecast is not a current observation, synthetic data is not provider evidence, delayed data is not fresh merely because it loaded, and imagery/raster is not converted into point evidence. Coverage status is reported, partial, out of coverage, or unknown, with known blind spots and time basis shown where available. A successful request, a clear/no-error status, an empty result, a missing record, or an unreported source does **not** establish clear conditions, provider agreement, trustworthy data, or a complete feed.

The evidence surface also reports provider attribution, license/terms information, source URL, retrieval time, source-record time basis, truncation/cache indicators, and absence meaning when available. These are context for review, not a trust score or an assertion that the source is complete. Existing provider panels remain the authority for imagery, raster, animated overlays, camera image bytes, and provider-only state.

## World-state time machine — first slice

Use **Capture loaded map state** to record the point observations already held by Atlas, the available provider-result summaries, and the displayed map center, zoom, and layer filters. Explicit source summaries supplied by a provider panel may also be retained; providers that do not emit summaries are not represented as having complete summaries. Capture is a separate, user-initiated action: it does not refresh a provider, start polling, enable network access, upload data, or add storage. Up to 10 captures are kept in this page's memory; each capture is bounded by 5,000 observations and a 2 MB payload cap. The oldest capture is dropped when the ten-capture limit is reached, and captures are cleared by the **Clear captures** action or a page reload. No provider was refreshed by capture.

Each captured record keeps its source, layer, ID, original record timestamp (`observedAt`), reported freshness, and source metadata already present on the record. Provider retrieval time is shown separately when supplied; Atlas capture time is always separate and never substitutes for source time. Forecast, synthetic, delayed, and geometric-estimate records retain their distinctions. Capture coverage gaps explicitly include excluded visual/provider-only surfaces, invalid or missing point records, empty source results, unknown or partial coverage, errors, and truncation where reported. Missing records or empty results remain unknown rather than being interpreted as absence.

Replay selects an exact captured state: it does not interpolate positions, invent earlier records, fetch data, or promote stale records to current. The map labels a replay as historical and not current. Comparisons match observations by source, layer, and ID and report added, removed, changed, or unchanged records. A difference is only a difference between captured datasets; it is not proof of event causality, provider trustworthiness, or an event beginning or ending. Snapshot comparison separately reports source-context summary changes (added, removed, changed, or unchanged metadata). Those source-context changes are not causality or a trust assessment, and an unreported source is not proof of no change.

Potential cross-source conflicts are unresolved and are checked only when records share the same layer and ID but come from different sources. The check compares overlapping data-bearing values such as point, confidence when present, and non-metadata properties; the UI shows the differing values for review. Freshness, retrieval/provider timestamps, coverage, truncation/cache state, attribution, license, terms, source URL, and other provenance/freshness metadata are excluded from conflict fields. The UI selects no winner and a reported conflict does not establish which source is correct. “No conflict identified” likewise does not establish agreement, accuracy, or completeness.

The capture excludes imagery, raster and animated overlays, camera image bytes, basemap tiles, and provider-only states outside the shared point/provider-summary surfaces; those remain in their provider panels. Imported data are not verified by capture, and capture does not grant permission to retain provider data: review each source's terms before using the feature with that source. No provider opt-in, keys, attribution, terms, or cancellation gates are changed.

## Operating boundary

Atlas is a read-only public-context display and a simulation-first reference, **not flight-ready and not a navigation display**. It has no weapon/effector controls, targeting, arming, or AI-to-command path. Aircraft telemetry remains receive-only; other Mark 2 features and their existing safeguards are preserved. This map change adds no deployment and no new license.
